# 自动提示优化

无需人工投入即可提升提示质量的实用技巧……

这篇文章最初发表在[我的 Substack](https://cameronrwolfe.substack.com/p/automatic-prompt-optimization)。

## 介绍

提示——尤其是大型语言模型（LLM）和其他类型的前沿模型——可以说是现代人工智能领域最具影响力的进步之一。通过编写自然语言指令，几乎任何人都可以利用大规模神经网络的强大功能来解决各种各样的实际问题。虽然前几代深度学习模型在性能方面已经取得了令人瞩目的成就，但 LLM 的优势远不止于此——它们使用起来非常直观。非专业人士也可以与这些模型互动，亲身感受它们的潜力，这使得人工智能研究获得了前所未有的关注。

> “通过以自然语言指令为条件，大型语言模型（LLM）展现出了作为通用计算机的强大能力。然而，任务表现很大程度上取决于用于引导模型的提示语的质量，而大多数有效的提示语都是由人类精心设计的。”——摘自[1]

尽管提示为LLM提供了一个直观的界面，但这个界面远非完美。许多模型对提示的细微变化过于敏感。调整提示的措辞或结构可能会导致错误且意想不到的结果。因此，编写有效的提示需要相当深厚的领域专业知识，并已成为一项炙手可热的技能。大多数提示都是通过反复试验和纠错的过程创建的，并且需要人工参与。我们只需不断调整和测试提示，凭借对提示——以及对被提示的那个 LLM——的理解，引导搜索找到表现良好的提示。

**自动改进提示语。** 提示语的编写需要大量的人工投入，而且本身就存在缺陷。为了缓解这些问题，近期的研究探索了自动提示语优化这一概念，即利用数据通过算法来提升提示语的质量。这种方法具有以下几个主要优势：

1. 寻找合适的提示所需的人工工作量较少。
2. 系统地搜索和发现提示，从而能够找到性能优于人类编写的提示。

提示优化技术使我们能够自动提升提示的质量，而无需依赖启发式方法和领域知识。本文将概述已发表的大量相关文献，重点介绍创建更优质提示的最实用技术。

## 预备知识：提示和优化

本文将主要探讨优化和提示工程的重叠之处，但我们必须记住，优化和提示工程这两个概念本身也是两个独立的研究领域。通过分别学习这两个概念，我们将能够理解如何将它们背后的关键概念结合起来，从而创建用于自动提升提示质量的算法。

### 什么是优化？

![优化函数](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/02.webp)

优化是指在某个函数（称为“目标函数”）中寻找最优解或最优值点的过程。通常，这意味着找到使函数值最小化（或最大化）的点；参见上文。通过找到这个最优值点，我们就实现了对函数的“优化”，即执行优化操作。*.* 优化领域已存在数个世纪，内容丰富、应用广泛且极具价值。优化目标函数的思想可用于解决大量重要任务，包括从交通路由到神经网络训练等各种问题。本文篇幅有限，无法对优化进行全面解释，但您可以参考许多相关资源。

**优化算法的类型** 人们已经提出了无数种优化算法。即使对于训练神经网络这一特定应用，也有[种类繁多的优化算法](https://www.ruder.io/optimizing-gradient-descent/)可供选择。尽管种类繁多，但优化算法大致可以分为两类：

1. 基于梯度
2. 无梯度

**基于梯度的优化** 反复执行以下步骤：*i) 计算函数的梯度；*ii) 使用该梯度更新当前解。梯度指向函数值（局部）递增的方向，因此我们可以利用梯度找到函数值较高或较低的区域。下图展示了这一过程，其中我们不断计算梯度，并沿梯度的反方向移动以最小化函数（即梯度下降）。

![梯度下降的示意图](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/03.webp)

机器学习从业者通常最熟悉基于梯度的优化算法。这些算法是反向传播的基础，反向传播几乎被普遍用于训练神经网络和其他机器学习模型。基于梯度的算法之所以流行，是因为它们既有效又高效！即使优化大量变量（例如，LLM 的参数），只需沿着梯度方向寻找解决方案，计算成本（相对而言）也很低。

**无梯度算法**是一类不使用梯度信息的优化算法；例如，[暴力搜索](https://www.geeksforgeeks.org/brute-force-approach-and-its-pros-and-cons/)和[爬山算法](https://www.geeksforgeeks.org/introduction-hill-climbing-artificial-intelligence/)就是两个基本的例子。无梯度优化算法有很多，但最流行的算法之一——*也是我们将在本概述中遇到的算法类型*——是进化算法（EA）；详见下文。

![（摘自[18]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/04.webp)

受生物进化思想的启发，进化算法维护着一个候选解“种群”，并反复进行以下操作：

- 通过变异和交叉等进化算子修改该群体成员（即候选解），以产生新的群体成员，模拟繁殖行为。
- 从种群中选出最优秀的成员——*基于某些目标函数*——继续进化（即适者生存）。

进化算法（EA）有很多变体[19]，但最常见的形式是遗传算法和差分进化算法。一般来说，与基于梯度的优化算法相比，进化算法的效率较低。例如，如果没有梯度信息，训练大型神经网络（例如，LLM）将非常困难。搜索空间非常大，因此调整模型参数、测量损失并期望找到更好的 LLM 并不能取得太大进展。

> “进化算法通常从包含 N 个解的初始种群开始，然后使用进化算子（例如，变异和交叉）在当前种群上迭代生成新的解，并根据适应度函数更新种群。”——摘自[16]

然而，进化算法也有许多优点；例如，这些算法能够很好地平衡探索和利用之间的权衡。基于梯度的算法只能产生单个解，而进化算法则维护着整个种群！这一特性对于某些类型的问题非常有用，因此进化算法在许多有趣的领域得到了实际应用，例如[演化神经网络架构](https://www.uber.com/blog/deep-neuroevolution/)或优化计算机网络拓扑结构[19]。

**利用 LLM 作为优化器。** 近年来，研究人员探索了将 LLM 用作无梯度优化器的想法。为此，我们向 LLM 提供关于当前问题解的信息（包括解的性能）以及优化轨迹（即先前解的历史记录）。然后，我们可以提示 LLM 生成一个新的（希望是更好的）问题解。通过测量新解的性能并重复此过程，我们创建了一种新型的优化算法。正如我们将看到的，这种基于 LLM 的优化技术经常用于优化提示信息。

![（来自 \[28\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/05.webp)

许多论文探讨了使用 LLM 作为优化器的主题。例如，文献[3]中的作者使用 LLM 来优化简单的回归问题并解决旅行商问题。研究人员还探索了以下方面：

- 将 LLM 与 EA 相结合 \[27, 28\].
- 使用 LLM 进行超参数优化 \[29\].
- 使用 LLM 实现 [神经架构搜索](https://en.wikipedia.org/wiki/Neural_architecture_search) 的自动化 \[30\].

> “我们并非正式定义优化问题并使用程序求解器推导更新步骤，而是用自然语言描述优化问题，然后指示 LLM 基于问题描述和先前找到的解迭代生成新的解。” *— 摘自 [3]*

### 提示工程基础知识

![](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/06.webp)

LLM 的通用文本到文本结构既直观又强大。我们无需让科学家针对每个待解决的任务训练专门的/狭义的模型，而是可以让（几乎）任何人通过提示以书面形式解释问题，并将该提示传递给 LLM，从而在无需（或只需极少）训练数据的情况下生成合理的解决方案；参见上文。提示的易用性释放了巨大的潜力，因为非机器学习领域的专家可以轻松地构建原型并展示 LLM 的强大应用 [22]。

> “LLM 对提示格式非常敏感；特别是，语义相似的提示可能导致截然不同的性能，而且最佳提示格式可能因模型和任务而异。”*——摘自[3]*

遗憾的是，LLM 对提示的细微变化非常敏感——*提示的措辞和结构细节会产生巨大影响*。这个问题使得非专业人士难以编写 LLM 提示[21]。因此，提示工程（即创建更佳提示的艺术）已成为一项合法、流行且实用的技能。本概述将主要关注自动改进提示的方法，但我们也会在此介绍一些提示的基础知识。

![包含所有组件的提示示例](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/07.webp)

**提示的构成要素** 虽然我们可以采用多种不同的方法来编写提示，但任何类型的提示通常都包含一些标准组成部分：

- *指令*：对模型预期输出的文字描述。
- *示例/范例*：提示中包含的正确输入输出对的具体示例（即演示）。
- *背景信息*：提示中提供给 LLM 的任何额外信息。
- *输入数据*：LLM 需要处理的实际数据（例如，正在翻译或分类的句子、正在总结的文档等）。
- *结构/指示符*：我们可以添加不同的标签、标题或组织字符串，以分隔或组织提示的各个部分。

上面展示了一个使用了所有这些组件的提示示例，但提示并非必须包含所有这些组件。我们可以根据待解决问题的具体细节或需求，有选择地使用它们。

**提示技巧。** 在之前的概述中，我们已经深入研究了不同类型的提示技巧：

- [实用提示工程](https://cameronrwolfe.substack.com/p/practical-prompt-engineering-part): 基本概念、零/少提示、说明等。
- [高级提示工程](https://cameronrwolfe.substack.com/p/advanced-prompt-engineering): 思路链 (CoT) 提示、CoT 提示的变体、上下文检索等等。
- [提示工程的现代进展](https://cameronrwolfe.substack.com/p/modern-advances-in-prompt-engineering): 近期提示研究（例如，工具使用、推理、程序辅助提示、长篇写作等）。

除了上面列出的概述之外，还有无数的在线资源可以了解更多关于提示工程的知识；例如，[学习提示](https://learnprompting.org/docs/introduction)、[提示指南（来自 The Gradient）](https://thegradient.pub/prompting/)、提示工程调查[23, 24, 25]等等。

**编写更佳提示的框架。** 提示工程是一门经验科学，主要基于反复试验。为了编写更佳的提示，我们应该不断地：*i)* 调整原提示，*ii)* 评估新提示的效果，*iii)* 选择更优的提示。我们还要确保提示不会过于复杂。原因有以下几点：

- 如果一个复杂的提示信息表现不佳，我们如何知道提示信息的哪个部分出了问题，需要修复哪些部分？
- 复杂的提示通常较长，会消耗更多 token，从而增加金钱成本。

鉴于以上原因，我们应该从一个简单的提示符（例如，少样本提示符或基于指令的提示符）开始提示符工程流程。然后，我们逐步增加提示符的复杂性——*通过添加少样本示例、使用诸如 CoT 之类的高级技术，或者仅仅调整指令*——同时持续监控性能变化。通过遵循此流程，我们可以改进提示符，并用性能的提升来证明增加复杂性的合理性；详见下文。一旦提示符的性能达到我们用例可接受的水平，该流程即告结束。

![](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/08.webp)

**提示设计本质上就是优化！** 如果我们仔细审视上述提示设计流程，就会发现这其实是一个优化问题！我们反复调整解决方案——也就是我们的提示——并分析新方案是否更优。在这个系统中，“优化者”指的是人类提示工程师，他们运用自身的判断力和提示知识来确定下一个最佳提示。然而，鉴于提示设计需要大量的试错，我们不禁会想，是否可以用自动化方法或算法来取代优化过程中的人工干预。

> “庞大且离散的提示空间使得提示工程的优化面临挑战，尤其是在只能通过 API 访问 LLM 的情况下。”——摘自[3]

**为什么优化提示信息如此困难？** 正如我们刚才了解到的，我们可以考虑使用两类优化算法来自动化提示信息设计流程。遗憾的是，由于以下几个原因，使用基于梯度的算法进行提示信息优化存在困难：

1. 对于许多 LLM，我们只能访问 API，这阻止了我们收集/使用任何梯度信息。
2. 提示由离散的标记组成，使用基于梯度的算法来优化离散的解决方案很复杂。

正如我们将在本概述中看到的，我们可以通过一些方法来避免这些问题，并使用基于梯度的优化来找到更好的提示。然而，由于上述原因，我们将主要依赖无梯度算法进行提示优化。事实上，进化算法（EA）是离散优化问题中最成功、应用最广泛的算法之一[26]！

## 早期关于提示优化的工作

优化提示语的想法并不新鲜。提示语的概念一经提出，研究人员就开始着手研究这个问题。本节将探讨一些早期关于提示语优化的研究工作，这些工作既应用于仅编码器的语言模型，也应用于 GPT 风格的 LLM。这些研究启发了后来许多如今常用的提示语优化技术。

### 生成合成提示

如上所述，由于提示信息中词元的离散特性，直接优化提示信息十分困难。一种解决方法是训练一个LLM来生成提示信息作为输出。这样，我们就可以训练生成提示信息的 LLM 的权重，而不是直接优化提示信息本身。这是一种实用且常用的技术。然而，正如我们将看到的，该领域的大多数工作都使用预训练的 LLM 来生成提示信息，而没有显式地优化 LLM 以生成更好的提示信息。

![（来自 [7]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/09.webp)

**指令归纳[7]**是最早探索使用预训练的 LLM 生成提示的方法之一。该技术旨在根据几个具体的（上下文相关的）任务示例作为输入，预测其对应的潜在任务。我们设计了一个包含多个输入输出示例的提示，并在提示的最后要求 LLM 通过完成“指令是……”序列来推断正在解决的任务；参见上文。

> “我们发现，在很大程度上，当使用足够大且能够遵循指令的模型时，生成指令的能力确实会出现。”——摘自[7]

LLM本身并不能直接解决这项任务；例如，一个预训练的[GPT-3](https://cameronrwolfe.substack.com/i/88082618/language-models-are-few-shot-learners)模型仅能达到 10%的准确率。然而，当模型经过调整以遵循指令时，它们在这个任务上的表现就会开始变得良好。 [InstructGPT](https://cameronrwolfe.substack.com/i/93578656/training-language-models-to-follow-instructions-with-human-feedback) 模型——*一个早期的、基于 GPT-3 的 LLM 变体* [*通过 RLHF 对齐以遵循人类指令*](https://cameronrwolfe.substack.com/p/the-story-of-rlhf-origins-motivations)——在指令归纳任务上达到了近 70% 的准确率。

![（来自 \[8\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/10.webp)

Self-Instruct [8] 是最早提出的利用语言模型（LLM）生成合成指令调优数据集的框架之一。该框架首先使用少量种子任务，然后引导语言模型（LLM）以这些种子任务为输入，生成可解决的新任务。之后，我们可以使用同一个语言模型（LLM）为每个任务创建具体的演示，并根据质量进行筛选。该流程的最终结果是生成一个由语言模型（LLM）生成的指令调优数据集，其中包含大量涵盖各种任务的输入输出示例。

> “Self-Instruct……通过引导预训练语言模型自身的生成过程，提升其指令执行能力。我们的流程会从语言模型中生成样本，然后过滤掉无效或相似的样本，再用这些样本来微调原始模型。”——摘自[8]

许多论文都使用类似的框架来生成合成指令。例如，文献[10]中的作者使用预训练的 LLM 来丰富提示种子集，并发现更适合分析 LLM 知识库的提示。此外，还提出了 Self-Instruct 的变体，例如该技术的[第二版](https://github.com/tatsu-lab/stanford_alpaca?tab=readme-ov-file#data-generation-process)，该版本在降低生成成本的同时提高了数据质量。

![（来自 [9]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/11.webp)

WizardLM [9] 设计了一种自指导式框架，专门用于创建高度复杂的指令调优数据集。该方法的核心是一种名为 EvolInstruct 的技术，它使用 LLM 迭代地重写（或演化）指令，以提高其复杂性。我们可以通过两种基本方式演化任何给定的指令：

1. *深入*：通过添加约束、要求更多推理步骤、使输入复杂化等方式使当前指令更加复杂（即，保持相同的指令并使其更加复杂）。
2. *广度*：增强指令调整数据集的主题覆盖范围、技能覆盖范围和整体多样性（即，为数据中尚未涵盖的主题生成指令）。

每种演化类型都有许多变体。下文提供了[9]中深度演化和广度演化的示例提示，不过 EvolInstruct 的实现还利用了许多其他提示。

![进化提示示例（来自 [9]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/12.webp)

基于这些提示演化策略，我们可以采用三步法：*i)*演化指令，*ii)*生成指令响应，以及*iii)*移除或剔除不可行或无法变得更加复杂的提示。通过遵循这些步骤，我们可以引导“自指导”框架生成包含高度复杂指令的合成数据集；详见下文。

![（来自 [9]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/13.webp)

### 软提示：前缀和提示调整

如果我们想改进提示，可以先从调整提示中的措辞或指令入手。这种方法称为“硬性”提示调整，因为我们是以一种离散的方式显式地更改提示中的词语（或标记）；参见上文。然而，硬性提示调整并非唯一的方法——*我们还可以探索对提示进行软性、持续性的更新*。

> “与提示不同，前缀完全由自由参数组成，这些参数不对应于实际的标记。” *— 来自 \[4\]*

**前缀调优[4]**是最早探索对 LLM 提示信息进行连续更新的论文之一。传统的模型微调会使用下游数据集训练模型的所有参数，而前缀调优则几乎不会改变模型的任何参数。我们的做法是在模型的提示信息前添加一个“前缀”（*或一系列额外的词元向量*），并直接训练该前缀的内容。然而，前缀调优并非仅仅更新输入提示信息，而是为底层模型中每个 Transformer 模块的输入添加一个可学习的前缀；下图展示了这一过程。

![带有可学习前缀的转换器模块](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/14.webp)

在前缀调优中，我们仅训练模型中添加的前缀。与直接训练前缀内容不同，文献[4]的作者发现，在将可学习的前缀与每一层的输入连接之前，先对其进行前馈变换，可以使训练更加稳定。这种为模型添加更多可学习参数的技术被称为“重参数化”。

![（来自 \[5\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/15.webp)

除了前缀之外的所有参数在训练过程中都保持不变，这大幅减少了微调过程中需要学习的参数总数——*如上图所示，减少了 100 倍甚至更多*。尽管如此，我们仍然可以通过前缀调优显著提升下游任务的性能；详见下文。

![（来自 \[4\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/16.webp)

尽管前缀调优在上述实验中表现良好，但\[4\]中微调实验所考虑的唯一基础模型是[GPT-2](https://cameronrwolfe.substack.com/p/language-models-gpt-and-gpt-2)，这意味着这些结果仍需用更现代的模型和数据集来证明。

**提示调优[5]**是前缀调优[4]的简化版本，两者同时提出。同样，我们从一个预训练的语言模型开始，并冻结模型的参数。我们不训练模型，而是创建一个“软”提示，即一个连接到语言模型输入开头的词元序列。然后，我们通过梯度下降法在数据集上训练软提示——*类似于训练任何其他模型参数*；详见下文。

![（来自 \[5\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/17.webp)

与前缀调优相比，提示调优仅在输入层（而非每一层）前添加前缀标记，并且无需重新参数化即可保持训练稳定。因此，提示调优学习到的参数总数远低于前缀调优。

> “我们……证明，仅靠提示调优（无需中间层前缀或特定任务的输出层）就足以与模型调优相媲美。”*——摘自[5]*

尽管可学习参数数量有限，但提示调优的效果却出奇地好，而且随着底层 LLM 规模的扩大，其性能甚至可以赶上端到端模型训练；详见下文。此外，提示调优的性能通常优于人工设计的提示——*但需要注意的是，人工设计提示的性能取决于编写提示的人*。

![（来自 \[5\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/18.png)

**软提示真的算是提示吗？** 软提示在性能上确实有效，但有人认为这些技术实际上并没有改进提示工程流程。提示工程的目标是找到一个在特定应用领域和所考虑的LLM下都能有效工作的文本提示。然而，提示和前缀调优并没有解决这个问题，反而消除了提示必须是离散/文本形式的限制。这些技术发现的“提示”只是一个通过基于梯度的优化学习到的连续向量。与其他模型参数一样，这个向量无法被人类理解，也不能移植到其他 LLM 上使用。

> “随着规模的扩大，这种方法的实用性会降低，因为计算梯度成本会越来越高，而且对模型的访问会转移到可能无法提供梯度访问权限的 API。”——摘自[1]

因此，前缀和提示符调优更接近于参数高效微调 (PEFT) 技术，而非自动提示符优化策略。我们并非寻找更优的提示符，而是向模型添加少量额外参数，并在保持预训练模型不变的情况下，直接在较小的、特定领域的数据集上训练这些参数。这些额外参数恰好被添加到我们的提示符中，而不是注入到模型的内部权重矩阵中。有关 PEFT 技术的更多信息，请参阅我关于此主题的概述[此处](https://cameronrwolfe.substack.com/p/easily-train-a-specialized-llm-peft)。

**基于 API 的访问。** 提示和前缀调优的另一个问题是，当我们只能通过 API 访问 LLM 时，这些技术无法使用。任何形式的基于梯度的训练都需要完全访问模型的权重，但 LLM API 只提供对模型输出的访问——*这些 LLM 简直就是一个黑盒*！因此，提示和前缀调优仅与[开源 LLM](https://cameronrwolfe.substack.com/p/the-history-of-open-source-llms-imitation)兼容，但研究人员已经尝试为此问题创建变通方案。

![（来自 \[6\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/19.webp)

InstructZero [6] 在软提示和 LLM API 之间插入了另一个 LLM。这个（开源的）LLM 可以经过训练，根据软提示和额外的任务信息生成文本指令（见上文）。然后，生成的指令可以像往常一样传递给 LLM API。简而言之，我们使用额外的 LLM 在将软提示传递给 API 之前将其“解码”为文本提示。为了提高生成指令的质量，我们可以使用[贝叶斯优化](https://arxiv.org/abs/1807.02811)，它生成的指令性能可以达到甚至超过其他自动提示方法生成的提示。

**关于软提示的更多研究。** 前缀和提示调整是目前最广为人知的软提示技术，但还有许多其他论文也探讨过这一思路。以下列举一些该领域其他值得关注的论文：

- [软提示的混合](https://arxiv.org/abs/2104.06599)是通过对提供给语言模型的整个提示进行微调而形成的——*无论是来自现有提示还是随机初始化*——以形成软提示，然后可以将该软提示与其他软提示混合或组合，以实现更好的任务性能。
- [WARP](https://arxiv.org/abs/2101.00121) 通过学习特定于任务的词嵌入来解决将语言模型适应多个下游任务的问题，这些词嵌入可以连接到模型的输入以解决不同的任务。
- [P-Tuning](https://arxiv.org/abs/2103.10385) 通过将一系列可训练的嵌入与模型的提示连接起来，解决了提示工程的不稳定性，其中模型可以与添加的嵌入一起进行微调，也可以保持冻结状态。
- [PADA](https://arxiv.org/abs/2102.12206) 通过训练语言模型首先预测解决问题的领域特定提示，然后使用生成的提示来实际解决问题，从而提高了 LLM 适应新领域的能力。

关于软提示的文章也很多。[Sebastian Rashka](https://sebastianraschka.com/)详细解释了[提示和前缀调整](https://magazine.sebastianraschka.com/p/understanding-parameter-efficient)，而[Lilian Weng](https://lilianweng.github.io/)则在她的[文本生成](https://lilianweng.github.io/posts/2021-01-02-controllable-text-generation/#smart-prompt-design)和[提示工程](https://lilianweng.github.io/posts/2023-03-15-prompt-engineering/#automatic-prompt-design)两篇文章中探讨了这一主题。

### 离散提示优化

![（摘自[11]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/20.webp)

正如我们所见，软提示在可解释性、跨模型复用性以及对基于 API 的 LLM 的适用性方面存在局限性。遗憾的是，这些局限性破坏了提示的几个关键优势。鉴于此，我们可能会思考，能否在保持这些特性的同时，自动优化提示。在提示技术的早期阶段，一些论文提出了寻找离散的“触发”标记的想法，这些标记可以包含在模型的提示中，以帮助解决某些特定问题。

> “编写提示语不仅耗时，而且尚不清楚相同的措辞是否对所有模型都有效，也不清楚哪些标准可以决定某种措辞是否最能引出所需信息。”——摘自[11]

**AutoPrompt** [11] 对离散的词元集合进行梯度引导搜索，以发现一组最优的附加词元，用于 LLM 的提示。该方法应用于 LLM 中的知识探测任务，结果表明，这些附加词元能够提升 LLM 在该任务中的可靠性和稳定性。通过使用触发词元，我们可以通过严格的（基于梯度的）搜索过程来优化 LLM 的性能，而无需通过手动试错来启发式地寻找最佳提示。

由于使用了梯度信息，我们在[11]中看到，AutoPrompt 用于编辑提示符的训练过程可能不稳定。作为一种替代方案，后续研究探索了通过强化学习(RL)来优化提示符。使用 RL 优化提示符的思路非常简单。首先，我们定义一个策略网络，它实际上是一个 LLM，用于生成候选提示符作为输出。然后，我们可以将该策略网络的奖励定义为它生成的提示符的性能！下图展示了该框架。

![使用强化学习优化 LLM](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/21.webp)

这种设置与通过[基于人类反馈的强化学习 (RLHF)](https://cameronrwolfe.substack.com/p/the-story-of-rlhf-origins-motivations)训练 LLM 非常相似。在这两种情况下，我们的策略都是 LLM，并且该策略通过生成标记来执行动作。一旦生成完整的序列，我们就计算该序列的奖励。在 RLHF 中，该奖励是奖励模型的输出，该模型代表人类偏好。对于提示优化，该奖励由提示的表现决定；参见上文。

**RLPrompt** [12] 是使用强化学习优化离散提示的最著名论文之一。生成提示的策略网络采用预训练的 LLM 实现。该模型的参数保持不变，但我们向模型添加了一个额外的前馈层，该前馈层通过强化学习进行训练；详见下文。

![（来自 \[12\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/22.webp)

该策略网络用于生成候选提示，这些提示会被另一个LLM接收以解决任务——*策略网络和接收提示的 LLM 不必相同*。奖励是通过衡量给定提示所达到的性能（例如，分类准确率或输出与给定风格的契合度）来获得的。这里，奖励函数取决于 LLM 生成的输出。因此，RLPrompt 框架中的奖励信号是不可预测的、复杂的，并且难以优化。尽管存在这个问题，文献[12]中的作者表明，可以使用各种奖励稳定技术来提高优化过程的可靠性。

![（来自 \[12\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/23.webp)

当应用于分类和风格迁移任务时，RLPrompt 生成的提示语表现优于微调和提示语调优策略（见上文）。然而，我们期望自动优化提示语以便人类轻松理解的目标却未能实现。RLPrompt 生成的提示语虽然与其他 LLM 结合使用时迁移效果良好，但往往语法错误百出，甚至有些“胡言乱语”。从某种角度来看，这一发现或许会让我们思考，提示语本身是否在某种程度上也是一种独立的语言。

> “最终得到的优化提示通常是语法错误的乱码；令人惊讶的是，这些乱码提示可以在不同的语言模型之间迁移，并保持显著的性能，这表明语言模型的提示可能并不遵循人类语言模式。”——摘自[12]

**TEMPERA** [13] — *受实例相关提示优化*（即针对每个输入动态优化提示）*工作的启发* — 采用不同的方法，利用强化学习在测试/推理阶段对提示进行调整。给定一个初始提示，我们可以通过以下方式编辑其属性：*i)* 修改指令，*ii)* 添加或删除少样本示例，*iii)* 修改 verbalizer（标签描述词）。我们可以通过强化学习训练智能体执行这些编辑操作，并将奖励定义为给定编辑前后性能的差异；详见下文。

![（摘自[13]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/24.webp)

TEMPERA 学习一个函数，该函数以原始提示、当前输入到 LLM 的查询、一组少样本示例以及一个 verbalizer 池作为输入，然后通过一系列编辑操作（例如，交换示例或编辑 verbalizer）生成最终提示。从强化学习的角度来看，我们的状态由当前提示给出，我们可以通过编辑提示来执行操作。为了表示状态，我们可以直接使用当前提示的文本。然而，文献 [13] 的作者选择通过预训练的 LLM 来嵌入该文本。通过这种方式，我们可以实现一个简单的策略网络，该网络：

1. 以状态/提示嵌入作为输入。
2. 生成要执行的操作/编辑作为输出。

TEMPERA 考虑的是对提示信息可执行的一组固定编辑操作，因此该动作空间是离散的！我们可以直接利用策略网络预测要执行的提示信息编辑操作。通过将奖励定义为给定编辑操作带来的性能提升，我们可以使用现成的强化学习算法（例如 PPO）来优化整个系统。这种方法被证明数据效率高，适用于分类任务，甚至对使用 LLM 解决更复杂的任务也很有成效。

![（摘自[13]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/25.webp)

**为什么这种方法有效？** 通过使用强化学习，我们最终可以实现一种用于优化离散提示的训练流程。与我们目前看到的其他方法相比，像 RLPrompt 这样的技术做出了两项关键改进，从而实现了这一点：

1. 我们使用 LLM 生成提示。
2. 我们根据生成的提示的质量来优化这个 LLM。

通过使用 LLM 生成提示，我们可以专注于优化 LLM 的（连续）权重，而不是离散的提示本身。指令归纳 [7] 或自指导 [8] 等技术也采用了类似的方法，但我们更进一步，利用强化学习 (RL) 来训练模型生成更好的提示。我们需要 RL 来进行这种优化，因为用于生成奖励的系统基于 LLM，因此不可微！换句话说，我们无法轻易计算梯度以用于优化。

## 自动优化 LLM 提示

既然我们已经了解了早期关于优化提示符的工作，接下来我们将学习一些关于自动提示符优化的最新热门论文。几乎所有这些论文都依赖于LLM的提示符优化能力。与传统的、成熟的优化算法相比，使用 LLM 作为无梯度优化器（可以说）不够严谨。然而，这类方法概念简单，易于实践应用，且非常有效，因此基于 LLM 的提示符优化算法变得非常流行。

### [大型语言模型是人类级别的提示工程师](https://arxiv.org/abs/2211.01910) [1]

![（来自 \[1\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/26.webp)

编写有效的提示需要大量的尝试和纠错。提示设计是一个黑箱优化问题——*我们事先并不知道提示与任何给定模型的兼容性如何*。在[1]中，我们看到了利用 LLM 提高人工提示设计效率的早期尝试之一。

> “我们将这个问题称为自然语言程序合成，并提出将其视为一个黑盒优化问题来解决，使用LLM来生成和搜索启发式可行的候选解。”——摘自[1]

本文提出的方法称为自动提示工程师（APE），它通过搜索由 LLM 生成的提示池，找到性能最佳的提示。该方案使用独立的 LLM 分别用于生成和评估提示。评估过程中，我们通过[零样本推理](https://cameronrwolfe.substack.com/i/117151147/zero-shot-learning)生成输出，并根据选定的评分函数对输出进行评估。尽管 APE 方法简单，但文献[1]表明，它能够找到性能与人类编写的提示相当甚至更优的提示，*这表明 LLM 在编写提示方面确实表现出色*。

![APE 的指令生成模板（来自 [1]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/27.webp)

**它是如何运作的？** APE 主要包含两个操作：*提议* 和 *评分*。对于提议操作，我们要求 LLM 为某个任务生成新的候选提示；以上提供了一组示例提示。如上所示，新指令的生成可以采用正向或反向的方式。在正向模式下，我们只需通过[下一个标记预测](https://cameronrwolfe.substack.com/i/136638774/understanding-next-token-prediction)生成新指令，这与使用 LLM 生成任何其他类型的文本完全相同。另一方面，反向生成基于[填充](https://ai.stanford.edu/blog/infilling-by-language-modeling/)（即，将缺失的文本/标记插入序列中间），而这在[仅解码器语言模型](https://cameronrwolfe.substack.com/p/decoder-only-transformers-the-workhorse)中是无法实现的。根据任务的不同，我们可能会调整指令生成模板的措辞。

![APE 的步骤（来自 [1]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/28.webp)

我们在[1]中看到，LLM 可以从先前的指令中推断出更好的指令。为了确定生成指令的质量，我们可以简单地使用另一个 LLM 以零样本方式对其进行评估，评估指标可以是输出准确率，也可以是更宽松的指标（例如，正确输出的对数概率）。每个生成的提示的评估都在一个固定的训练集上进行，该训练集贯穿整个提示优化过程。与微调相比，通过 APE 进行提示优化所需的训练样本要少得多。优化完成后，我们通常会在一个预留的测试集上评估最终的提示。

![（来自 \[1\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/29.webp)

为了达到最佳性能，我们在[1]中看到，应该让 LLM 生成约 64 个用于选择的提示。如果我们生成更多提示，性能方面的收益就会开始递减——*找到的最佳提示的准确率并没有显著提高*。

> “虽然这种方法提高了提案集的整体质量，但得分最高的指令往往在更多阶段中保持不变。” *——摘自[1]*

**迭代生成。** 我们还可以使用 APE 以迭代的方式优化提示。在这种设置下，我们仍然要求 LLM 提出新的指令，计算每条指令的分数，并选择得分最高的指令。更进一步，我们可以重复此过程，将这些生成的指令作为输入，以类似的方式将其用作上下文，提出更多指令变体，并选择性能最佳的提示；详见下文。

![迭代 APE（来自 \[1\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/30.webp)

利用这种策略，我们可以探索 LLM 提出的不同提示变体。然而，我们在[1]中看到，迭代式 APE 仅提高了所探索提示集的整体质量。APE 发现的最佳提示的性能在任何迭代次数后都保持不变；详见下文。因此，*迭代式 APE 的额外成本可能没有必要*。

![（来自 \[1\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/31.webp)

**APE 能否发现更优的提示？** APE 的评估基于其在多种场景下编写有效提示的能力，包括零样本提示、少样本提示、CoT 提示以及引导 LLM 行为（例如，更诚实地回答问题）的提示。实验结果表明，APE 能够找到优于人类编写的提示。具体而言，APE 在 24 项指令导入任务中均优于人类编写的提示，在 21 项 BIG-Bench 任务中也优于 17 项；详情请见下文。

![（来自 \[1\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/32.webp)

通过分析 APE 提出的提示，我们甚至可以推导出一些编写有效提示的实用技巧。在许多情况下，这些技巧能够很好地推广到各种任务中，并教会我们如何正确地提示某些模型。我们还在 [1] 中看到，指令候选的性能随着 LLM 大小的增加而提高，*这表明在 APE 中使用较大的 LLM 来提出新指令是有帮助的。*

### [自动提示优化](https://arxiv.org/abs/2305.03495) \[2\]

尽管 APE 效果不错，但它用于优化提示符的过程是随机且无方向的。我们只是简单地使用 LLM 生成大量新的提示符变体，然后选择性能最佳的提示符。该算法中没有迭代优化过程。相反，我们完全依赖于优化器 LLM 生成大量有前景的提示符变体的能力，这些变体可以在一次迭代中得到评估，从而找到更优的提示符。

> “该算法使用批量数据来构建自然语言梯度，这些梯度用于批评当前的提示，就像数值梯度指向误差上升的方向一样。然后，通过沿梯度相反的语义方向编辑提示，将这些自然语言梯度传播到提示中。” *— 来自 \[2\]*

从正确的角度来看，使用 LLM 优化提示与传统的基于梯度的优化类似。在 [2] 中，作者提出了一种名为自动提示优化 (APO) 的提示优化技术，其灵感正是来源于此。APO 是一种通用技术，仅需一个（小型）训练数据集、一个初始提示以及对 LLM API 的访问权限即可运行。该算法使用批量训练数据来导出“梯度”——*仅是对当前提示局限性的基于文本的评价*——这些梯度用于指导对提示的编辑和改进，模拟梯度更新；详见下文。

![（来自 \[2\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/33.webp)

**优化框架。** APO 旨在根据自然语言梯度，对提示信息进行离散改进。这些梯度通过以下方式得出：

- 使用 LLM 对训练数据集执行当前提示。
- 根据某些目标函数衡量提示的性能。
- 使用 LLM 来评价此提示在训练数据集上的性能的关键局限性。

由此得到的梯度简单地概括了当前提示中存在的各种问题。利用这个概括，我们可以引导 LLM（*以梯度和当前提示为输入*）修改现有提示，从而减少这些问题。APO 会迭代地应用这些步骤来找到最优提示。下图展示了该框架。

![（来自 \[2\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/34.webp)

**梯度和编辑。** APO 创建一个递归反馈循环，通过以下方式优化提示：*i)* 收集当前提示在训练数据上产生的错误，*ii)* 通过自然语言梯度总结这些错误，*iii)* 使用梯度生成提示的几个修改版本，*iv)* 选择最佳的编辑提示，以及 *v)* 重复此过程几次。

> “我们用基于文本的对话来模拟梯度下降的步骤，用 LLM 反馈代替微分，用 LLM 编辑代替反向传播。” *— 来自 \[2\]*

为了生成“梯度”，我们向 LLM 展示当前提示在训练数据集上出现的错误示例，并要求模型提出这些错误的原因。然后，我们将这些原因作为修改提示的上下文；详见下文。

![使用自然语言梯度编辑提示（来自[2]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/35.webp)

在每次迭代中，我们会对当前提示生成若干次修改——*修改次数是优化过程的一个超参数*。此外，我们可以通过显式地生成每个提示的多个措辞来扩展搜索空间，这种方法在[2]中被作者称为[蒙特卡洛](https://en.wikipedia.org/wiki/Monte_Carlo_method)采样；详见下文。

![APO 中的蒙特卡洛采样（来自 \[2\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/36.webp)

**搜索与选择。** 通过生成每个提示的多个变体，我们可以使用[束搜索](https://en.wikipedia.org/wiki/Beam_search)来寻找最优提示。换句话说，我们在每次迭代中维护几个最佳提示的候选词，为每个提示提出 N 个修改，然后*通过衡量其在训练集上的性能*，选择最佳的 B 个修改词保留到下一次迭代中；详见下文。

![使用束搜索迭代地选择最佳提示](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/37.webp)

正如我们所预期的，如果我们持续评估整个训练数据集上的所有候选提示，束搜索的成本会非常高。然而，我们在[2]中看到，我们可以使用多臂老虎机技术（尤其是与最佳臂识别问题相关的技术）来提高搜索效率。虽然这种方法的细节超出了本文的范围，但其核心思想是，我们可以使用统计方法来选择哪些提示值得进行充分评估，而不是简单地评估整个训练数据集上的每一个提示。

**效果如何？** 我们使用 APO 对 GPT-3.5 进行评估，以指导其完成四种不同的基于文本的分类任务，包括越狱检测、仇恨言论检测、虚假新闻检测和讽刺检测。*为什么只考虑分类问题？* 之所以明确选择分类任务来评估 APO，可能是因为这些问题的目标函数定义起来比较简单——*我们可以根据分类准确率来评估每个提示*。对于复杂或开放式任务，定义目标函数并非易事，这使得像 APO 这样的技术的应用变得不那么直接。

![（来自 \[2\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/38.webp)

如上所示，APO 在所有数据集上均优于其他最先进的提示优化算法。值得注意的是，我们发现 APE（即上图中的蒙特卡洛 (MC) 技术）的性能不如 APO，这表明通过在提示优化过程中添加更具体的方向（即自然语言梯度）可以带来显著的提升。我们在 [2] 中看到，APO 可以将初始提示的性能提升高达 31%，超过了其他技术所取得的提升，尽管 APO 需要调用 LLM API。

### [GRIPS：用于提示大型语言模型的无梯度、基于编辑的指令搜索](https://arxiv.org/abs/2203.07281) \[14\]

> “我们提出了一种无梯度教学提示搜索（GRIPS）方法，这是一种通过迭代、局部、基于编辑且无梯度的搜索来改进教学提示的自动化程序。” *— 摘自 [14]*

在提示优化过程中，我们可以使用启发式策略生成新的提示变体供考虑，而不是使用 LLM 来编辑提示。在 [14] 中，作者提出了 GrIPS，这是一种无梯度方法，它通过迭代应用一组固定的启发式编辑操作来搜索更优的提示。与我们目前看到的方法类似，GrIPS 以人工编写的提示作为输入，并返回一个改进的、经过编辑的提示作为输出。

**启发式提示搜索。** GrIPS 既可以应用于基于指令的提示，也可以应用于包含上下文示例的提示（如下所示），但它只专注于改进指令——*我们并不试图优化 GrIPS 中示例的选择*。为了搜索所有可能的提示，我们首先创建一个初始提示，然后迭代地对该提示进行一系列修改。之后，我们可以测试修改后的提示在训练示例池上的性能，从而确定哪些修改后的提示效果最佳。

![（摘自[14]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/39.webp)

此流程与我们目前所见的技术有些类似，但它不同之处在于，它是在搜索过程中对提示信息应用一系列启发式编辑，而不是依赖 LLM 生成编辑后的提示信息版本。此技术可适用于任意类型的 LLM，包括通过 API 公开的 LLM。

**搜索详情** GrIPS 的优化框架如下所示。我们从一条由人工编写的基础指令开始搜索过程。在每次迭代中，我们选择一定数量的编辑操作应用于该基础指令，从而生成若干新的候选指令。然后对这些候选指令进行评分，以便找出最佳指令。如果最佳候选指令的得分高于当前基础指令，则将其作为后续的基础指令。否则，我们保持当前基础指令不变并重复上述过程。这是一个贪婪搜索过程，当基础指令的得分在多次迭代后仍未提高时，搜索过程终止。

![（摘自[14]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/40.webp)

与 [2] 类似，我们可以通过在每次迭代中维护一组指令，轻松地将这种贪婪搜索过程调整为束搜索。然而，这种修改会增加搜索过程的成本，因为每一步都需要评估更多的候选提示。

**编辑类型。** 在 GrIPS 中，我们始终在短语级别进行编辑，从而能够在保持提示结构的同时对其进行有意义的修改。为了将提示分解为短语，我们可以使用[成分句法分析器](https://nlpprogress.com/english/constituency_parsing.html)。然后，我们会对提示中的短语执行四种不同的编辑操作：

1. *删除*：从指令中删除某个短语的所有出现次数，并将删除的短语存储起来，以便在添加操作中使用。
2. *交换*：给定两个短语，将指令中所有出现的第一个短语替换为第二个短语，反之亦然。
3. *释义*：将说明中所有出现的某个短语替换为该短语的释义版本。
4. *添加*：对先前迭代中删除的短语进行采样，并将其添加到随机短语边界处的指令中。

**实际应用。** GrIPS 主要在 [Natural Instructions 数据集](https://instructions.apps.allenai.org/) 的二元分类任务上进行评估。与 [12] 中的观察结果类似，我们发现 GrIPS 发现的提示往往能提高准确率，但并非总是连贯一致。优化后的提示包含语义生硬且令人困惑的措辞。尽管如此，我们在 [14] 中发现，使用 GrIPS 优化基础指令始终能将各种 LLM 的准确率提高 2% 到 10%。此外，手动重写提示（*甚至在某些情况下基于梯度的提示调优*）的性能通常不如 GrIPS，GrIPS 被发现最适合优化特定任务（而非通用）指令；详见下文。

![（摘自[14]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/41.webp)

### [大型语言模型作为优化器](https://arxiv.org/abs/2309.03409) \[3\]

> “我们并非正式定义优化问题并使用程序求解器推导更新步骤，而是用自然语言描述优化问题，然后指示 LLM 基于问题描述和先前找到的解迭代生成新的解。” *— 摘自 [3]*

目前最流行、应用最广泛的提示优化技术之一是提示优化（OPRO）。然而，OPRO 的功能远不止于优化提示。它是一种通用的优化算法，其工作原理如下：

1. 用自然语言描述优化任务。
2. 向优化器 LLM 展示优化任务的先前解决方案示例及其目标值。
3. 要求优化器 LLM 推断出问题的新/更好的解决方案。
4. 通过评估器 LLM 测试推断出的解决方案。

通过重复上述步骤，我们创建了一个极其灵活且无需梯度的优化算法。我们无需用数学公式正式描述要解决的问题，只需用自然语言解释即可。这样的描述足以让 OPRO 执行优化，这使得该算法具有广泛的适用性，并且易于扩展到新的任务。

![（来自 \[3\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/42.webp)

在采用正确的采样策略后，该优化算法的轨迹相对稳定，这再次表明 LLM 能够从过去的解中学习，从而提出新的、更好的解决方案；参见上文。尽管 OPRO 可以应用于许多问题，但我们在[3]中看到，该算法对于自动提示优化尤其有用。首先，我们将了解 OPRO 的工作原理，然后探讨如何利用它来优化提示。

![（来自 \[3\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/43.webp)

**OPRO 框架** OPRO 遵循的高级步骤如上所述。在优化过程的每个步骤中，OPRO 都会根据一个元提示生成新的解决方案。该元提示包含对优化问题的文本描述以及先前已提出的解决方案。给定元提示，我们会​​一次性生成多个新解决方案。通过在每个步骤中生成多个候选解决方案，我们可以确保优化轨迹（相对）稳定，因为 LLM 有多次机会生成可行的解决方案。

接下来，我们基于目标函数（例如准确率）评估每个新解，并将最佳解添加到元提示中，以供下一步优化。通过这种方式，我们选择最佳解传递到优化过程的下一次迭代。我们的目标是找到一个能够优化目标函数的解，一旦 LLM 无法提出能够改进目标的新解，优化过程即终止。

![OPRO 的关键组成部分（来自 [3]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/44.webp)

**OPRO 的关键组成部分。** 从这个框架中我们可以看到，OPRO 的优化过程包含两个主要组成部分（如上图所示）：

- *优化器*：以元提示作为输入，并提出新的解决方案。
- *评估器：*以解决方案作为输入，并计算目标值。

优化器始终以LLM 的形式实现。为了成功应用 OPRO，我们必须选择一个足够强大的 LLM 作为优化器，因为从元提示提供的上下文中推断出最佳解决方案需要复杂的推理能力。此外，我们在 [1] 中看到，规模更大的 LLM 往往更擅长这项任务。

根据所解决的问题，评估器也可以实现为 LLM，*但优化器和评估器不必是同一个 LLM*。例如，线性回归问题的评估器很简单（即，我们可以直接从解中计算目标值），但提示优化问题需要使用评估器 LLM 来衡量每个提示的输出质量。

> “虽然传统的优化方法通常需要相当大的训练集，但我们的实验表明，少量或一小部分训练样本就足够了。” *— 来自 [3]*

OPRO 优化算法需要训练数据和测试数据。我们使用训练数据集在优化过程中计算目标值，而测试集则用于在优化过程结束后评估生成解的最终性能。与大多数优化算法相比，OPRO 所需的训练数据量非常少。

**关于元提示的更多信息。** 元提示提供了优化器 LLM 提出更优问题解决方案所需的所有必要上下文。元提示包含两个主要组成部分：

1. 对优化问题的文字描述。
2. 先前的解决方案及其目标值（即优化轨迹）。

优化轨迹经过排序，最佳解出现在元提示的末尾。除了这些核心信息外，我们还从训练数据集中随机选取了一些示例，以展示预期的输出格式，以及创建新解时需要遵循的一般性指导（例如，“力求简洁”或“生成一条能够最大限度提高准确率的新指令”）。下面展示了一个提示优化任务的元提示示例。

![（来自 \[3\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/45.webp)

**OPRO 的性能。** 在 [3] 中，OPRO 在 [GSM8K](https://huggingface.co/datasets/openai/gsm8k) 和 [Big-Bench Hard](https://github.com/suzgunmirac/BIG-Bench-Hard) 数据集上进行了评估。在这些数据集上，OPRO 发现的提示分别比人工编写的提示性能高出 8% 和 50%。与 APE [1] 等先前的方法相比，OPRO 能够找到性能更优的更复杂的指令；详见下文。有趣的是，发现的指令风格往往会因所使用的优化器 LLM 的不同而有很大差异。

![（来自 \[3\]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/46.webp)

**高级推理系统 (o1).** 如前所述，从优化轨迹中推断新解是一个复杂的推理问题。我们已经看到，更大的 LLM 更擅长解决此任务 [1]，这表明我们可以从具有更强推理能力的更强大的优化器 LLM 中获益。此外，*提示优化是一次性成本*。我们只需优化一次提示，但优化后的提示通常会在下游应用程序中使用更长时间。因此，使用更昂贵的优化器 LLM 的成本可以通过其生成的提示的生命周期来摊销。

最近提出的基于 LLM 的推理系统，例如[OpenAI 的 o1](https://openai.com/index/introducing-openai-o1-preview/)，为提示优化开辟了新的可能性。这些系统经过训练，遵循一套复杂的推理流程，模型可以动态地判断是否需要更多计算资源来解决复杂问题；详情请参见[此处](https://www.interconnects.ai/p/reverse-engineering-openai-o1)。这种先进的推理策略在某些情况下可能代价高昂；例如，o1 在响应提示之前可能需要“思考”[超过一分钟](https://x.com/axioma_ai/status/1834355853576556769)。然而，对于复杂的推理问题，在推理阶段使用额外的计算资源可能是值得的。对于自动提示优化而言，优化器 LLM 的响应延迟和成本远不如生成的提示的质量重要，这使得它成为这些高级推理系统的主要应用。

> “我们推出了 OpenAI o1，这是一个全新的大型语言模型，它利用强化学习进行训练，能够执行复杂的推理。o1 会先思考再回答——它可以在回复用户之前进行长时间的内部思考。” *—* [*source*](https://openai.com/index/learning-to-reason-with-llms/)

### 通过演化优化提示

我们目前看到的提示优化策略都是从人工编写的提示（或一组提示）开始，然后通过迭代的方式进行优化：

1. 生成提示的变体。
2. 从这些变体中选择效果最好的提示。

在某些方面，这种优化过程可以被视为一种进化算法（EA）。它会维护一个提示语种群，并随着时间的推移对其进行变异和选择。我们通常使用种群规模为 1 的算法（除非使用束搜索），并通过提示 LLM（或使用启发式的、基于编辑的策略）来修改当前提示语，从而实现种群的变异。受此启发，研究人员最近探索了将进化算法应用于提示语优化的更明确的策略。正如我们将看到的，这些算法与我们目前所看到的算法并没有太大的区别！

![（摘自[15]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/47.webp)

**遗传提示搜索 (GPS)** [15]（如上图所示）采用遗传算法自动发现高性能提示。首先，使用一组手写提示（或种群）实例化该算法。然后，我们可以通过以下操作对这些提示进行变异：

- *回译*：将提示翻译成 11 种其他语言之一，然后再翻译回英语。
- *完形填空*：屏蔽提示中的几个标记，并使用预训练的语言模型（例如，[T5](https://cameronrwolfe.substack.com/p/t5-text-to-text-transformers-part)）来填充它们，从而生成新的提示。
- *句子延续*：提示 LLM “写出两个意思相同的句子”，并将当前提示作为第一句。

这些策略均可对现有提示语群体进行变异，从而生成新的提示语变体。接下来，我们可以使用预留验证集对生成的提示语进行评分，以确定哪些提示语应保留在下一轮迭代（或下一代）进化过程中。该算法优于人工提示语设计，在某些情况下甚至优于提示语调优。

> “提示语中的短语序列可以被视为典型进化算法中的基因序列，这使得它们与自然进化过程相符。”——摘自[16]

EvoPrompt [16] 再次利用进化算法 (EA) 的概念，创建了一个性能良好且收敛速度快的提示优化器。EvoPrompt 从一组手动编写的提示语开始，使用两种主要的进化算子——变异和交叉——生成新的提示语。在每一代中，通过在一个预留的验证集上测量提示语的性能，选择并保留性能最佳的提示语进行后续进化。

根据定义，进化算子以序列作为输入，并输出修改后的序列。传统上，算子独立应用于序列中的每个元素——*我们更新每个元素，却不知道它周围的元素是否发生了变化。* 对于提示优化而言，这种方法存在问题，因为提示中的所有标记都是相互关联的。

![（摘自[16]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/48.webp)

为了解决这个问题，EvoPrompt 通过提示实现进化算子，并依靠LLM的专业知识以逻辑方式演化提示。上文展示了用于通过遗传算法优化提示的交叉和变异提示示例。然而，EvoPrompt 支持多种进化算法，远不止遗传算法！例如，我们在下面看到一组可用于实现差分进化策略以进行提示优化的提示。EvoPrompt 框架足够灵活，可以即插即用地替换不同的进化算法。

![（摘自[16]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/49.webp)

EvoPrompt 在多个任务上与闭源和开源 LLM（例如 Alpaca 和 GPT-3.5）进行了测试，结果表明其性能优于 APE [1] 和 APO [2] 等算法。在大多数情况下，EvoPrompt 的差分进化变体优于遗传算法变体；详见下文。

![（摘自[16]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/50.webp)

Prompbreeder [17] 是在 EvoPrompt 之后不久提出的。这两种技术背后的理念相似：

- 它们都以人类编写的提示语为基础。
- 它们都通过向 LLM 发出提示来实现变异和交叉等进化算子。
- 它们都是通过衡量验证集上的性能来进行选择。

这些技术的主要区别在于，Promptbreeder 不仅仅优化任务提示——*用于实现进化算子的提示也会被优化*！这种方法使我们能够在提示优化算法本身中引入自我改进机制。

> “也就是说，Promptbreeder 不仅改进了任务提示，还改进了那些能够改进这些任务提示的变异提示。”——摘自[17]

在推理基准测试中，Promptbreeder 的性能优于多种强大的提示策略（例如，[思维链](https://arxiv.org/abs/2201.11903) 和 [计划与解决](https://arxiv.org/abs/2305.04091) 提示）。其他提示优化算法通常会在迭代次数增加时出现收益递减和性能饱和的情况[1]，而 Promptbreeder 会随着时间的推移动态调整优化过程，从而发现更适合解决复杂任务的复杂提示。

![（摘自[17]）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@45b2e72da3fb2ab31aed589bfd6a779314c7faff/ai-insights/2026-06/16/images/automatic-prompt-optimization/51.webp)

## 实用技巧和要点

在本概述中，我们已经了解了多种提示优化技术，包括直接从数据中学习软提示的方法、利用 LLM 作为无梯度优化器的方法、使用强化学习训练更擅长生成提示的模型的方法等等。下面我们将总结所有这些研究的关键要点。

**为什么提示优化很难？** 正如我们所见，提示优化并非普通的优化问题，原因有以下几点：

1. 我们正在尝试优化的提示是由离散的标记组成的。
2. 在大多数情况下，我们缺乏梯度信息。

如果我们使用 LLM API，可用于改进提示的信息非常有限。此外，提示的离散性也使得基于梯度的优化算法难以应用。成功的提示优化算法通过以下方式避免了这些问题：*i)* 采用类似于进化算法的无梯度优化算法；*ii)* 依靠 LLM 从先前尝试过的提示中推断出更优提示的能力。

**LLM 是优秀的提示设计者。** 近期提示优化论文的主要结论之一是，LLM 非常擅长编写提示。假设我们提供正确的上下文信息，只需迭代地引导 LLM 对提示进行评价和改进，我们就能创建出功能强大的提示优化算法。规模更大（能力更强）的 LLM 往往更擅长这项任务。因此，将 OpenAI 的 o1 等高级模型应用于提示优化是一个尚未被充分探索的有趣机会。

**我们应该使用什么？** 由于我们已经了解了许多提示优化算法，我们可能不知道应该实际使用哪种技术。我们看到的大部分研究都很有用。然而，基于LLM的提示优化器（例如 OPRO [3]）是迄今为止最直接、最实用的提示优化技术。我们可以使用这些算法自动改进我们编写的任何提示，生成一个更易于人类理解的更佳提示。OPRO 易于使用且效果显著，因此在LLM从业者中广受欢迎。OPRO 的开源实现已在[此处](https://github.com/google-deepmind/opro)提供。

**人工干预是否仍然必要？** 虽然提示优化技术可以大幅减少人工提示设计的工作量，但完全取代人工提示工程师不太可能。我们目前所见的所有算法都需要人工提示工程师提供初始提示，作为优化过程的起点。此外，像 OPRO 这样的技术在实践中也需要人工干预/指导才能找到最佳提示。简而言之，*自动提示优化技术本质上是辅助性的*。这些算法可以自动完成一些基本的人工提示设计工作，但并不能完全取代人工提示工程师。然而，值得注意的是，随着时间的推移，LLM 对提示的细微变化的敏感度自然会降低，这使得提示设计在总体上变得不那么必要了。

**提示优化的局限性。** 我们目前所见的提示优化算法有助于改进提示的措辞和基本结构。然而，构建一个高性能的 LLM 系统还需要考虑更多因素。例如，我们可能需要使用检索增强生成（RAG）技术，在提示中添加额外的数据源，找到最佳的少样本示例等等。自动化这些更高层次的选择超出了我们目前所见提示优化算法的能力范围，但研究人员正在开发诸如 DSPy [31] 之类的工具，这些工具可以自动化 LLM 系统的高层设计和底层实现。
