# 什么是编排者？为什么软件需要编排者？

一个新的职位名称，属于那些靠指挥系统、agent 和结果来交付系统的专家

现在人人都在说开发者的时代要结束了。我明白。那些负责编写样板代码或搭建 CRUD 应用框架的开发者确实做到头了——模型几秒钟就能搞定，这类开发者也不会再回来了。但宣称编程时代终结的人忽略了一点：软件行业的多个领域，正在涌现一个新的职位名称。

架构师和开发者正在转变为编排者——一个人指挥过去需要整个团队才能完成的工作。这种转变的影响范围将远远超出软件领域，但我亲眼目睹它的地方是软件工程。

![编排者站在机器与后果之间。（图片由 Anthropic 提供）](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@7e0b7dc1fd05a94669b0ad6f51dfda14611e8685/ai-insights/2026-08/06/images/whats-an-orchestrator-and-why-does-software-need-one/01.webp)

编排者懂得如何开发软件，但他们的工作不再是编写代码，而是监督系统、编排工具和 agent，并把生成出来的组件组合成必须能在生产环境中运行的东西。而“编排者”和“软件开发者”之间最重要的区别在于，编排者较少关注交付软件，更多关注编排那些既能运行软件、也能开发软件的系统。

过去用于弄清数据库模式或对象模型结构的技术专长，如今将用于指导一系列子系统——它们已经承担起大部分战术层面、行级别的决策。2023 年的“开发者”专注于决定 React 应用如何存储状态，而 2027 年的“编排者”专注的是一个 DESIGN.md 文件：它为某个子系统设定标准，该子系统负责将分析数据与客户反馈融合，从而推荐、测试和实施网站变更，而这又是一套更大、更自主的业务运营方式的一部分。

### **编排委托智能系统**

虽然现在大家都把所有东西都称为“agent”，但我还是想提出一个想法。编排者可以、也将会使用一些类似于我们今天在用的那些更“agentic”的做法的系统，例如 Hermes、OpenClaw，或其他所有开始自称“agent”的系统。我开始觉得这个词被滥用了。从我们今天使用的技术往后退一步，我认为“编排者”的职责，是协调属于“委托智能”这个新类别的系统。

几十年来，我们一直把所有东西都称为“人工智能”。这个术语，再加上“生成式人工智能”和“推理引擎”，无法准确描述我们开始在实践中看到的现象。一个拥有记忆、能以一定独立性运行的 agentic 系统，展现出的是“委托智能”，而“委托”一词至关重要：它意味着这类系统始终可以追溯到一个负责的操作者——在这里就是编排者。

> 向编排者转变的根本，是自动化、生产力和问责制的结合。随着组织、公司和政府开始利用委托智能来支持更自主的设计、运营和工程方式，建立问责制的需求将日益增长。如果你的企业在一组自主 agent 上运行关键基础设施，那么发生故障时，必须回答的问题之一就是：“这套委托智能是根据谁的授权在运行？”

### 编排者的生态系统：通才与专才

有编排者，也有技术专家。编排者的标志是走向通才型专长，因为专家的能力如今大多已经存在于模型之中。你仍然需要几个专家，但不需要每项技术都配一个——而且其中一些专家本身也会是专才型编排者。事情会变得很复杂。

你要找的是能端到端理解全局的通才型编排者。可以把编排者想象成“文艺复兴式”的专家级程序员——通常是有二十多年经验、理解软件开发端到端生命周期的人。正是这些人在成为编排者，而这正在改变整个 IT 部门的构成。我们不再是程序员了。

让我用自己的亲身经历来说明新的现实是什么样。我最近要给一系列自出版的有声书加上 DRM——一种[听不见的水印](https://en.wikipedia.org/wiki/Audio_watermark_detection)，它会把与订单相关的特定数据编码进音频文件，这样如果我在外面发现了其中某个文件，就能识别出是谁买的。我不是叠加音频水印方面的专家，但我确实懂得如何编写处理音频文件的代码。

### 编排：从数月到数分钟

这项任务过去会花掉我数周甚至数月的时间，不久前我还会先创建一个 git 仓库、打开 IDE 来启动项目。但到了 2026 年，事情不是这么做的了。

两周前我编排这套系统的创建时，只花了 20 分钟，工具就给了我三个维度的高强度加密水印与指纹识别——基本上相当于 3 位隐写音频专家的工作成果。

好吧，我撒谎了——其实是 40 分钟。前 20 分钟我让模型提出 5 种不同的方案，好让我从中选出合适的那个。但我想强调的是，我要求系统给出 5 个不同的方案，然后对每个方案的长期成本和可运维性建模。我还要求它考虑客户体验、为每个方案列出优缺点矩阵，最后给出推荐。

这一切都由一个已经跟踪内容开发好几个月的系统完成，它利用客户认知、分析数据和产品设计，在动手实现之前先确定了要交给编排者的那组方案。

### 你的工作不是写代码，而是编排。

我现在工作的一部分，是把这些工具用在创造之外——用在构思、产品设计和质量工程上。编排者之所以存在，是因为这个人知道该问什么问题。仅仅四年前，这件事需要我花三个月、外加一个大团队才能完成，而这次我没读每一行代码就把它发布了。

> 坦白说，这是个很奇怪的处境，三年前的“我”要是听说自己实现了某个东西、代码却不是自己写的，一定会非常不舒服。事实上，我最初听到 Steve Yegge 说他应该不再读自己的代码时，反应非常负面，至今对这个观点仍有保留；但我得说，在我自己的实践中，我开始不读自己的代码了——因为那不是我的代码。

和很多读到这篇文章的程序员一样，我也经历了一次程序员的身份时刻——要学会坦然接受：把可能没逐行读过的东西发布到生产环境。那里大概有十万行代码——多到读不完——而且说实话，这已经不是我的工作了。我是编排者，如果还试图跟上每一行代码，效率会极低。

我不是那种凭感觉写代码的人，也不是“公民开发者”——这个词我讨厌到想骂人，因为它根本用错了。我是那种写得出代码、但决定把这项任务委托出去的人，交给一个手上信息比我这辈子能收集到的还多的系统。而尽管这些系统——像 agent 这样的委托智能工具——能在几分钟内实现一套系统，它们仍然需要人来在方向上表态。而且我认为，我们仍然需要一个人在场并承担责任。

编排者懂得足够多，能看懂替他们做出来的东西，也知道出问题时如何深挖细节。他们懂调试，对什么有效、什么无效有判断，并且对自己知道什么、不知道什么很诚实。

### 编排者作为收尾者

有争议的部分来了。这绝对不是关于“普及技术”。有一种迷思认为任何人都可以拿起这些工具写代码，这没错——任何人都可以写代码，但并非每个人都能以可扩展且安全的方式把它交付到生产环境。

> 我的一位同事最近写道，用生成式人工智能启动项目很容易，难的是完成它们。把东西交付到生产环境所需要的努力、精力和技术专长，和以往一样多。

任何人随便抓起一个生成式人工智能工具就能造出技术上的完美产物——这个迷思即将破灭。如果你构建了一套复杂的技术系统，却没有一个人负责编排它的创建与运行，那么总有一天你得花钱请人来替你做这件事，而那个人会收你一大笔钱。

### 编排者会为意外做准备：支持能力

我刚才说的那套 DRM 系统——我没读每一行代码，但在发布之前，我确保自己弄清了后续支持的基线。虽然我把创建它的权限委托给了一个 agent，但我同时也要求这个 agent 记录代码位置、架构、实现思路，并生成一套文档，以便在 AI 不可用时也能用来调试和支持它。

在把它部署到生产环境之前，我是否从头到尾读过这本“飞行手册”？没有。但我知道油门表在哪儿，如果需要在没有自动驾驶的情况下把这架飞机降下来，我做得到。这是新角色的职责之一：为“离线”做规划，把各种意外情况想清楚。

关键在于，万一需要调试，我有足够的资格看懂 AI 替我写的这本飞行手册；而如果 AI 明天就消失，我可以自己把它重建出来。对许多通过 AI 入门编程的人来说，情况并非如此，这会造成一种对工具的依赖，而这种依赖需要被管理起来——其中一种管理方式，就是靠那些经过认证的编排者：他们既能创建系统，也能在没有工具的情况下支持系统，尤其是在受监管的关键领域。

### 使组织适应新兴角色

情况变化很快——一个编排者相当于 20 到 30 个开发者，外加几支 QA 工程师团队。虽然我们仍然需要产品人员和为客户着想的人，但技术工作正在向那个指挥它的人身上集中。

在你问出口之前——为什么不直接把这叫做架构师？因为架构师从来就没成立过。如果你在有架构师的公司待过，你会发现他们往往是那些不再写代码、真要写可能也写不出来的人，他们在那儿实际上就是告诉别人该做什么。这是一个已经过了黄金期的职位——如今，任何思考代码的人都应该以某种方式写代码。

编排者不是那种整天盯着 IDE、不与人交流的程序员；他们理解的是完整的端到端流程——不只是技术系统里的数据流，还包括业务如何运转、如何自主适应。他们是技术型的，但同时也专注于提供监督，并且是那个负责决定哪些智能可以被委托出去的人。

**那么，我们该如何造就编排者？** 不是靠训练营或六周的证书课程。这需要学徒制——好几年的学徒制，就像我们培养医生和律师那样。你在一个知道该关注什么的人手下做事，通过看他们如何决策来学习。

这些员工能造成真正的破坏，他们是行走的责任风险。公司为写代码的人买保险时，面对的是一类风险；而当你为生产力高出一百倍的专业人士投保时，他们同时也背着一百倍的责任。保险费率、监管和认证要求都会随之上升。医生要买[医疗事故责任险](https://www.ama-assn.org/practice-management/sustainability/medical-liability-malpractice-insurance)，因为他们的决定关乎人的性命。

> [专业工程师](https://www.nspe.org/resources/licensure/what-pe)必须持照，因为工程关乎公共安全。编排者正走在同一个方向上。

如果把时间快进 20 或 30 年，我们今天称为程序员的人将会是编排者，而他们看起来会更像医生和律师，而不是像现在这群写代码的人。

代码仍会是这份工作的一部分，但不是主要部分。
