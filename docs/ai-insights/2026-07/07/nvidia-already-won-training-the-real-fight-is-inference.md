# 英伟达已经赢得了训练。真正的战斗在于推理。

![专用硬件架构正在加入人工智能推理时间延迟的竞赛。\[来源：作者\]](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@55352042c140f22735346f8b2836e13302a72a75/ai-insights/2026-07/07/images/nvidia-already-won-training-the-real-fight-is-inference/01.webp)

## 介绍

过去几周，我一直在深入研究一个特定的问题，最终我确信，大多数关于人工智能硬件的讨论都跑题了：争论的焦点在于训练——谁能搭建最大的集群，谁能训练出下一个前沿模型。而从硬件角度来看，这个问题根本没什么好讨论的。如果你要训练一个大型模型，那就买英伟达。就这么简单。GPU 的原始性能加上 CUDA 软件生态系统，优势如此悬殊，以至于硬件选择根本就不是选择。除非出现真正意义上的全新模型架构来颠覆格局，否则这场竞赛还没开始就已经结束了。

但训练是一次性的。模型只需构建一次，然后每天运行数十亿次，为每个用户、每个提示服务，实际上会一直运行下去（也就是说，直到几个月后你弃用今天的前沿模型为止）。运行模型的过程称为推理，而推理才是未来几年真正赚钱的地方。此外，与训练不同——这一点对本文至关重要——推理在硬件方面完全是开放的。

而真正让我深陷其中的，正是这个转折。推理看似是一个问题，实则是两个，其中最要紧的那一半是与时钟的赛跑。出错，用户只能眼睁睁地看着 cursor 闪烁；正确，答案瞬间呈现。而这个时钟，也就是推理延迟，恰恰是英伟达通用 GPU 原本就不是为赢下它而设计的，一批公司已经注意到了这一点。

![来源：作者](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@55352042c140f22735346f8b2836e13302a72a75/ai-insights/2026-07/07/images/nvidia-already-won-training-the-real-fight-is-inference/02.webp)

接下来是对其中五家公司的简要介绍：Cerebras、Groq、d-Matrix、Etched 和 Taalas。有些通过重新思考内存来解决问题；有些则重新思考芯片本身的形态。它们都不是要在训练上击败英伟达，而是都在争夺英伟达留在桌上的那一半。

## GPU 究竟是什么？

让我们先从在位者说起，因为其他一切都是对它的反应。如果你对 GPU 了如指掌，可能觉得没什么意思，但请耐心听我说完。

GPU 就像一台功能强大的通用并行计算器。它最初是为绘制视频游戏图形而设计的，这意味着它需要并行地对数百万个像素进行简单的数学运算。这恰好与运行神经网络的工作性质大致相同——无休止的矩阵乘法——这也是 GPU 被重新用于人工智能的原因。关键在于“通用”二字。一块英伟达芯片今天可以轻松运行语言模型，明天可以运行蛋白质折叠模型，下周还可以运行天气模拟。只要是可并行化的，它并不在意你交给它什么任务。

这种灵活性是英伟达占据主导地位的第一大支柱。第二大支柱是 CUDA——这个软件层让程序员能够告诉 GPU 该做什么。近二十年来，英伟达在此基础上构建了一个庞大的生态系统：库、编译器、工具，以及数百万开发者积累的习惯。世界上几乎所有的 AI 框架都首先针对 CUDA 进行了优化。因此，即使是拥有更快芯片的竞争对手，也必须说服开发者放弃他们已经熟悉的生态系统和社区，这远比仅仅速度快要难得多。

强大的并行处理能力和 CUDA 的护城河使得训练领域完全被英伟达垄断，这一点毋庸置疑。但一旦我们从构建模型过渡到运行模型，情况就完全不同了。要了解个中缘由，我们需要探究使用 AI 模型进行推理时究竟发生了什么。

## 推理：双头计算九头蛇

我们来讨论一下延迟。训练是以周为单位的批处理作业，因此零星的几毫秒延迟在总时长面前可以忽略不计。推理则恰恰相反：有真人在等待每一个 token，每一毫秒的延迟都会立即被感知到。正是这一点，几乎是本文中提到的所有挑战者都着力解决的问题。

但延迟背后隐藏着微妙之处，因为 LLM 推理并非单一类型的工作，而是两种。当同时服务众多用户时，你需要不断地兼顾两个截然不同的阶段。

### 第一部分：预填充

第一部分——预填充——帮助 LLM 理解你的输入内容。当收到新的请求时，模型会一次性处理整个提示，通过一次大型矩阵乘法运算，注意力机制会消化你输入的所有内容。每个 token 同时并行处理。它会在短时间内对芯片进行高强度运算，并且非常适合批处理：你可以将多个用户的提示堆叠在一起，一次性处理。这是大规模并行工作，正是 GPU 的强项。

### 第二部分：解码

第二部分——解码——速度较慢且顺序执行。一旦理解了提示，模型就会逐个 token 生成答案，每个新 token 都依赖于前一个。无法通过批处理绕开这个顺序；它本质上是一步一步进行的。这也是所谓的“内存墙”发挥作用的地方（稍后会详细介绍）。模型权重的不断搬运，加上不断增长的 KV 缓存，使得整个过程受限于内存速度，而非计算能力。

![来源：作者](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@55352042c140f22735346f8b2836e13302a72a75/ai-insights/2026-07/07/images/nvidia-already-won-training-the-real-fight-is-inference/03.webp)

这就是矛盾所在。如果两个阶段都在同一块 GPU 上运行，大量涌入的预填充工作可能会阻塞正在进行的解码，导致现有用户突然发现答案在句子中间停顿，这个问题被称为*预填充干扰*。有趣的是，一种越来越流行的解决方案是所谓的“解耦”：不再强迫一块芯片同时服务两个阶段，而是将预填充阶段运行在渴求并行的硬件上，将解码阶段运行在为快速、可预测但顺序执行的工作而调校的硬件上。

## 内存墙：人人都在攻击的裂缝

如前所述，当芯片运行 LLM 时，瓶颈通常不在于计算能力。现代芯片的乘法运算速度极快，瓶颈在于取来要相乘的数字。模型的权重（数十甚至数百 GB）必须一遍又一遍地从内存搬进芯片中负责运算的部分，模型每生成一个 token 都要如此。计算单元最终只能闲置，等待数据到达。工程师们称之为“内存墙”，而这正是下文每一家公司都试图撬开的裂缝。

要了解为什么内存是问题所在，你需要了解芯片可以使用的三种主要内存类型，因为它们之间的区别会反复出现：

DRAM（动态随机存取存储器）是一种廉价、高密度、高容量的存储器，它位于距离处理器最远的位置。其变体，例如手机和笔记本电脑中使用的 LPDDR 以及消费级显卡中使用的 GDDR，都能以极低的成本存储海量数据。但问题在于速度。一次 DRAM 访问需要 100 纳秒以上，更重要的是，连接 DRAM 和芯片的总线数据传输速度不足以喂饱数千个 GPU 计算单元。对于每生成一个 token 都要让数十 GB 权重流过芯片的模型来说，普通的 DRAM 就像一根拴在消防栓上的吸管。任何严肃的 AI 加速器都不会用普通 DRAM 给计算单元供数，这也是 HBM 必须被发明出来的原因。

高带宽内存 (HBM) 是业界最终选择的解决方案。它是一种高密度内存，堆叠成高耸的微型塔状结构，紧挨着芯片放置在同一封装内，但并不位于芯片内部。HBM 也是 2026 年 AI 内存领域的领军者，其供应呈现出典型的寡头垄断格局：截至 [2026 年 6 月](https://siliconanalysts.com/tools/hbm-analysis)，SK 海力士以约 50-55% 的市场份额领先，三星以 35-40% 的市场份额紧随其后，美光则占 5-10%，整个市场基本上就由这三家瓜分，目前尚无第四家竞争者出现。正是由于这种市场集中度，HBM 的短缺而非计算能力的短缺，成为了整个 AI 建设浪潮中最严峻的制约因素之一。然而，由于数据仍然需要离开内存堆栈并传输到芯片内部，HBM 在延迟和能耗方面仍存在一些不足，这为后续挑战者留下了可乘之机。

SRAM（静态随机存取存储器）是直接集成在芯片上的存储器，已经存在了[几十年](https://en.wikipedia.org/wiki/Static_random-access_memory)。它与 DRAM 的根本区别在于其存储比特的方式：SRAM 不使用需要不断刷新的电容器，而是使用稳定的晶体管电路，这使得它速度极快，每次访问的能耗也非常低。读写操作可以在几纳秒甚至更短的时间内完成，而且由于它集成在芯片内部，因此不存在外部总线瓶颈。实际上，这使得 SRAM 成为唯一速度足够快，能够持续为现代张量核心或矩阵单元提供满负荷运行的存储器。

![来源：作者](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@55352042c140f22735346f8b2836e13302a72a75/ai-insights/2026-07/07/images/nvidia-already-won-training-the-real-fight-is-inference/04.webp)

因此，下面每一个设计的核心权衡说起来都很简单。DRAM 出局。SRAM 速度极快但容量很小。HBM 容量大但速度慢。英伟达押注 HBM，这给了它容量和灵活性。少数几家公司审视了这一个妥协，选择了绕过这堵墙的不同路径。

## Cerebras：让芯片和问题一样大

Cerebras 审视了内存墙，并提出了一个非常直白的问题——在 GPU 上，HBM 已经位于同一封装内、距离芯片仅几厘米，但即使这段微小的旅程也成了瓶颈。那么，为什么不走到逻辑上的极端，设计一块巨大的硅片，装下足够容纳 LLM 工作负载的 SRAM 呢？

![来源：https://www.cerebras.ai/](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@55352042c140f22735346f8b2836e13302a72a75/ai-insights/2026-07/07/images/nvidia-already-won-training-the-real-fight-is-inference/05.webp)

通常情况下，一块直径 300 毫米的圆形硅晶圆会被切割成数百个相同的小芯片，这样做是有充分理由的，主要原因在于良率。制造过程会在晶圆上散布微小的缺陷，而单个缺陷就可能毁掉整块芯片，因此芯片越大，一出厂就报废的可能性就越高。将晶圆切成上百个小裸片，几个有缺陷的几乎无关紧要；但要把整片晶圆做成一块芯片，从统计上看，几十个缺陷就足以使其报废。正是这笔缺陷账，才是之前没人造出晶圆级芯片的真正原因。Cerebras 的诀窍是[绕过它进行设计](https://www.cerebras.ai/blog/100x-defect-tolerance-how-cerebras-solved-the-yield-problem)：晶圆上铺满了数十万个相同的微小核心以及冗余线路，当缺陷击坏一个核心时，芯片只需绕过它即可。Cerebras 表示，这种方案使其缺陷容错率比传统设计高出约一百倍。

最终成果是晶圆级引擎 3（Wafer Scale Engine 3），一块餐盘大小的单芯片。[它在晶圆上就装有 44GB](https://arxiv.org/abs/2503.11698)（!）的 SRAM。最后这个数字才是关键所在。SRAM 一直以来都是速度快但容量小的那一档；高端 GPU 的裸片上也只有几十 MB 的 SRAM。通过将整个晶圆视为一块芯片，Cerebras 的片上内存容量大约是传统处理器的 1000 倍，足以把整个 LLM 放进现存最快的内存里，而无需从 HBM 流式传输。正因如此，其内部带宽达到了惊人的 21PB/s。与 NVIDIA H200 的 4.8TB/s 相比，Cerebras 的带宽大约是其 4375 倍。

然而，缺点在于，44GB 的闪电般快的 SRAM 毕竟只有 44GB，装得下一个全精度的中等规模模型，但装不下大型模型。参数量远大于约 300 亿（取决于量化方式）的模型将无法容纳。那怎么办？只能把多块晶圆拼在一起，迫使数据离开 SRAM 的舒适区，严重伤害延迟，重新引入单晶圆设计本来要消灭的芯片间延迟。只要模型小到能装进单块晶圆，Cerebras 就是应对内存墙的绝佳答案。

## Groq：让芯片完全可预测

Groq 攻击了另一个弱点：GPU 平均速度很快，但其时序不可预测，导致效率低下。

GPU 的设计目标是并行执行海量工作。由于不同的线程和内存访问完成的时间各不相同，硬件会在运行时动态调度工作，在任务间切换，隐藏内存延迟，并依靠缓存保持忙碌。这种灵活性正是 GPU 擅长并行预填充阶段的原因。但这同时也让其时序变得不稳定，而这种不稳定性对顺序解码阶段来说是毒药，因为在解码阶段，你希望每一步都花费相同、可预测且最小的时间。

Groq 的芯片称为 LPU（语言处理单元），采用了与 GPU 截然相反的方法。它并非在运行时决定执行什么操作，而是几乎所有操作都[由编译器预先规划好](https://medium.com/the-low-end-disruptor/groqs-deterministic-architecture-is-rewriting-the-physics-of-ai-inference-bb132675dce4)，整个执行计划在程序运行前就已确定，数据移动和计算逐周期地进行编排。LPU 用编译时规划换掉了 GPU 的动态即兴发挥，从而实现了惊人的可预测的、优化的性能，带来极低的延迟。

![来源：作者](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@55352042c140f22735346f8b2836e13302a72a75/ai-insights/2026-07/07/images/nvidia-already-won-training-the-real-fight-is-inference/06.webp)

与 Cerebras 类似，Groq 也以 SRAM 形式将内存留在芯片上，也同样要缴 SRAM 的容量税：每个 LPU 仅能容纳几百兆字节，对于一个完整的模型来说远远不够，因此大型模型必须分布在数百个互连的芯片上。英伟达在每块芯片旁边放一大池 HBM，而 Groq 用的则是一片由小型、高速、编排紧密的芯片组成的海洋。

证明这种方法重要性的最有力证据并非来自基准测试，而是来自英伟达自身。2025 年 12 月，英伟达与 Groq 达成了一项价值约 [200 亿美元](https://techcrunch.com/2026/05/29/after-nvidias-20b-not-acqui-hire-ai-chip-startup-groq-reportedly-raising-650m/)的授权协议，将其技术和部分工程团队并入自己的平台。当在位者花 200 亿美元把挑战者的想法收入麾下时，这就是市场在确认这个想法是真的。在 GTC 2026 大会上，这笔交易变成了一款把解耦理念落到实处的产品：Groq 技术以 [Groq 3 LPX](https://developer.nvidia.com/blog/inside-nvidia-groq-3-lpx-the-low-latency-inference-accelerator-for-the-nvidia-vera-rubin-platform) 的形式再次出现，这是一款与英伟达下一代 [Vera Rubin 平台](https://futurumgroup.com/insights/nvidia-gtc-2026-day-1-can-nvidias-ecosystem-accelerate-the-inference-inflection/) 共同设计的机架级加速器，其中 Rubin GPU 处理并行预填充，而 Groq LPX 芯片则接管对延迟敏感的解码。黄仁勋称之为极致协同设计，并声称这种组合在万亿参数模型上每兆瓦的吞吐量最高可提高 35 倍。

## d-Matrix：在内存中执行算术运算

d-Matrix 和其他所有人一样，也把内存墙视为核心问题，但提出了所有方案中最巧妙的绕行。如果昂贵的部分是把权重从内存搬到计算单元，那就别搬了：直接在数据已经所在的地方做计算。

这种被称为存内计算的方法，挑战了计算机设计中最古老的假设之一——冯·诺依曼架构。在这种架构中，内存和处理是分离的两个地方，数据在它们之间不断通勤。这种通勤正是内存墙的构成。d-Matrix 的[数字存内计算 (DIMC)](https://www.servethehome.com/d-matrix-corsair-in-memory-computing-for-ai-inference-at-hot-chips-2025/) 将算术运算直接构建到存储模型权重的 SRAM 结构中，因此许多运算就发生在数据已经所在的位置，而无需在芯片上来回穿梭。从某种意义上说，它比 HBM 更进一步——HBM 位于计算裸片旁边——甚至比传统 SRAM 也更进一步，后者虽然在裸片上，但仍然把内存和计算当作分开的两个街区。

![来源：作者](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@55352042c140f22735346f8b2836e13302a72a75/ai-insights/2026-07/07/images/nvidia-already-won-training-the-real-fight-is-inference/07.webp)

面对英伟达，d-Matrix 的卖点并非极致的通用性能，而是极致的推理效率。GPU 是一个功能强大的引擎，需要不断地来回移动权重和激活值，而 d-Matrix 的 Corsair 加速器则专门设计为几乎不移动它们，从而降低能耗并挤出延迟。

## Etched：制造一款只会一种技巧的芯片

前三个挑战者都以各自的方式攻击内存。后两个则攻击完全不同的东西：芯片应该能运行不止一种东西，这个理念本身。

我们目前讨论过的所有芯片，即使是那些比较特殊的，也仍然是可编程的；它们可以运行不同类型的神经网络。Etched 提出的问题是：既然如今几乎所有重要的 AI 模型都构建在单一架构——Transformer——之上，这种灵活性是否还值得付出代价。

要看懂这个赌注，你需要了解 GPU 和 ASIC 的区别。GPU 是通用型的：它可以运行多种工作负载，因此极为灵活，但它的一部分硅片和功耗总是花在特定任务永远用不到的能力上。ASIC（专用集成电路）则恰恰相反。它为一类狭窄的计算而造，由于不在通用性上花费分毫，它在自己那一件事上可以快得多、效率高得多，而对其他任何事都毫无用处。GPU 是一间摆满工具的多功能车间；ASIC 是一台为出色完成某一道生产工序而造的单一机器。

![来源：作者](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@55352042c140f22735346f8b2836e13302a72a75/ai-insights/2026-07/07/images/nvidia-already-won-training-the-real-fight-is-inference/08.webp)

Etched 的芯片 Sohu 是一款只运行 Transformer 的 ASIC。它在物理上就无法运行较早类型的神经网络，例如用于图像处理的卷积网络或 Transformer 之前的循环网络。作为交换，Etched 声称 Sohu 在 Transformer 推理上快得多也便宜得多，并[引用数据](https://theaiworld.org/news/etcheds-500m-sohu-chip-takes-aim-at-nvidia)称，在大型 Llama 模型上生成 token 时，速度约为 15 倍，成本约为十分之一，功耗约为九分之一。这些数据是该公司自行发布的，而非独立基准测试的结果，因此需要谨慎对待，但方向是明确的。

耐人寻味的是，与前三家不同，Etched 完全没有放弃 HBM：据报道，Sohu 每颗芯片使用 144GB 的 HBM3E，甚至超过了英伟达 H100。这就露了底：Etched 打的不是内存战争。它的赌注是纯粹的专业化。面对英伟达“什么都能跑”的承诺，它给出的是相反的答案：我们只跑一样东西，跑到完美。风险也同样纯粹：如果 Transformer 有朝一日被新架构赶下王座，一块只能运行 Transformer 的芯片就会变成极其昂贵的废品。

## Taalas：将模型烧录到硅片上

然后是 Taalas，它把专业化的逻辑推到了绝对的、甚至有点烧脑的结论。Etched 为一类模型构建硬件，而 Taalas 为某一个特定的已训练模型构建硬件。

在其他所有芯片上，包括 Etched 的芯片，权重都存放在内存中，需要时才被取出，而搬运权重正是内存墙的最大单一来源。Taalas 从根上攻击这一点。它没有把权重存成数据，而是[直接把它们蚀刻进芯片的电路](https://www.sdxcentral.com/news/chip-designer-taalas-bets-on-hard-wired-ai-chips/)。权重不再从 SRAM 或 HBM 加载，而是成为硬件本身的一部分。原本的一次内存访问，变成了一个在固定逻辑中传播的信号。这并没有完全废除内存，芯片仍然需要工作内存来存放激活值和 KV 缓存，但它消除了每生成一个 token 就要在芯片上搬运数十亿参数的需要，而这正是所有数据搬运中最大的一项。结果不只是效率提升，而是吞吐量的阶跃：针对 Llama3.1–8 模型的早期系统[已经展示了](https://www.eetimes.com/taalas-specializes-to-extremes-for-extraordinary-token-speed/)每秒远超 17,000（!）个 token 的速度，而 Cerebras 约为 2,000，Groq 约为 600，Nvidia Blackwell 一代硬件约为 350。

![来源：作者](https://cdn.jsdelivr.net/gh/genesislab-io/beatai-assets@55352042c140f22735346f8b2836e13302a72a75/ai-insights/2026-07/07/images/nvidia-already-won-training-the-real-fight-is-inference/09.webp)

这是本文中最极端的权衡，而且直接源于其设计：芯片与单一模型焊死在一起。如果不制造新的硬件，就无法加载新的权重、进行微调或升级到更新的模型。Taalas 的回答是制造速度：与其每次都设计全新的处理器，它声称可以与台积电合作，只需修改少量层，就能在大约两个月内将训练好的模型转化为量产芯片。

这与英伟达的理念截然相反。英伟达销售的是灵活的处理器，并允许软件在其基础上发展演进；新模型以代码的形式出现。而 Taalas 则颠覆了这种关系，让模型本身成为硬件。英伟达押注未来充满不确定性，灵活性至关重要。Taalas 则认为，对于足够流行且稳定的模型而言，将其固化进硅片所带来的效率，足以弥补失去更改能力的损失。

## 谱系：从通用到冻结

从这五家公司退后一步看，一个优美的模式便会显现。它们并非五个随机的想法，而是同一条线上的几个点——逐步用灵活性，换取推理所奖励的速度与效率。

· [**NVIDIA**](https://nvidia.com/)**：**通用型 GPU 平台，针对训练和推理的大规模并行性进行了优化。具有无与伦比的灵活性，但并非为确定性低延迟而设计。

· [**Cerebras**](https://cerebras.ai/)**：**晶圆级芯片，具有巨大的片上 SRAM 和带宽，可将整个模型保存在现存最快的内存中，最适合以极快的速度运行中小型模型。

· [**Groq**](https://groq.com/)**：**确定性数据流架构，提前固定调度，专为超低延迟、逐 token 解码而设计。

· [**d-Matrix**](https://d-matrix.ai/)**：**数字存内计算，直接在内存阵列内执行算术运算，以最大限度地减少数据移动。

· [**Etched**](https://ethced.com/)**：**一款只运行 Transformer 的 ASIC，用全部灵活性换取纯粹的专业化，也是唯一一家保留 HBM 而非打内存战争的挑战者。

· [**Taalas**](https://taalas.com/)**：**模型被编译进硅片，权重固定在线路中，对单个模型极其高效，对其他任何模型毫无用处。

从这张图中可以明显看出两点。首先，没有人真正声称要在训练前沿模型这项庞大而灵活的工作上取代英伟达，在那里，原始算力和 CUDA 仍然占据绝对统治地位。他们的目标是 AI 的日常运行成本，也就是每天运行数十亿次的部分，因为延迟的成败就取决于此，而英伟达的通用性在这里最不必要。

第二点是，整个谱系其实是围绕一个问题的一场漫长争论：为了逃离内存墙，你愿意交出多少灵活性？英伟达一分不让，以效率为代价。Taalas 全部让出，换来了极致的 token 生成速度。其他所有厂商都介于两者之间，各自坚信自己找到了最佳平衡点。
